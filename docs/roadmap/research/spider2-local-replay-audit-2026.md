# Spider2 local enterprise-SQL replay audit (2026)

## Spider2 pinned main (2026-01-30)

**Repo:** [xlang-ai/Spider2](https://github.com/xlang-ai/Spider2) at
[`01a4c67c1e3f6ab9032716b050a927abbb245f65`](https://github.com/xlang-ai/Spider2/tree/01a4c67c1e3f6ab9032716b050a927abbb245f65)

Spider2 had no tags and no GitHub releases when audited on 2026-07-30, so
the source and every external archive are pinned by hash. The repository is
MIT-licensed. This audit covers local Spider2-Lite SQLite and Spider2-DBT
DuckDB surfaces. It contains no task prompts, SQL, result rows, or database
contents.

## Decision

| Surface | Declared | Empirically self-consistent | Frankengate decision |
|---|---:|---:|---|
| Spider2-Lite local | 135 tasks, 30 database families | Upstream gold SQL passes 16/24; all 135 have result evaluation records | Audit all result artifacts, then create schema-family splits from the 135 |
| Spider2-DBT | 68 tasks | 59 strict; 62 with three deterministic filename aliases | Curate 60 from the 62 clean tasks |
| Spider DBT transcripts | Generated by runner; none shipped | Not OTel, OpenInference, or ATIF | Repair runner, then adapt typed actions and observations into the canonical trajectory |

Spider2 should be the complex, external-validity layer after the simpler Defog
causal replay works. It tests codebase navigation, schema scale, dialect
knowledge, DBT repair, and external-document grounding. It should not replace
the small PostgreSQL cohort used to debug experimental controls.

## Configuration

### Spider2-Lite

| Setting | Source behavior | Consequence |
|---|---|---|
| Timeout | CLI option is deleted and unused | Queries are not bounded by the advertised control |
| SQLite root | Evaluator reads directly below `resource/databases` | Disagrees with the README extraction path |
| Numeric tolerance | Absolute `0.01` | Must be declared and domain-justified |
| Column names | Ignored | Wrong projections can pass |
| Extra columns | Permitted | Sensitive or irrelevant output can pass |
| Order handling | Sorts column vectors independently | Can destroy row relationships |
| Missing values | NaN can become zero | Missing and numeric zero can compare equal |

### Spider DBT agent

| Setting | Default | Consequence |
|---|---:|---|
| `max_steps` | 30 | Ordinary tool actions currently execute twice |
| `max_memory_length` | 25 | Model-facing history is truncated |
| model | `gpt-4o` | Moving alias; replace with an exact release |
| temperature | 0 | Record with every run |
| `top_p` | 0.9 | Record with every run |
| maximum observation | 30,000 characters | Longer output is truncated |
| action timeout | 200 seconds | Double execution can consume it twice |

## Environment

The compatibility audit used Python 3.14.2, `dbt-core` 1.12.0,
`dbt-duckdb` 1.10.1, DuckDB 1.5.5, and pandas 3.0.5. These are audit pins,
not upstream pins: the upstream Dockerfile leaves much of the stack unpinned.
Local gold-versus-gold checks require no model credentials.

The agent source supports OpenAI, Azure, Gemini-proxy, and Groq credentials.
Raw runs can therefore contain secrets in model responses, shell actions,
observations, and system messages. Raw trajectories must stay outside Git and
pass the Frankengate import redaction and authority checks.

## Empirical audit

Spider2-Lite has 135 local records, 30 local database families, 135 local
evaluation records, and eight referenced external-knowledge files, all
present. Its 328 result CSVs cover all 135 task IDs. Only 24 published local
gold SQL files exist; the upstream evaluator accepts 16 and rejects eight.
There were no SQL-execution errors in that 24-file check, so the failures are
oracle/comparator disagreements rather than unavailable databases.

Spider2-DBT declares 68 tasks. The start archive has 68 DuckDB files but swaps
one declared member for an undeclared database. The gold archive has 65
DuckDB files. Seven expected filenames are absent: three are deterministic
aliases and four have no published gold database. Gold-versus-gold passes
59 strict tasks and all three alias repairs. One further database lacks a
required table, and one NaN-bearing comparator case is non-reflexive. The
audited recommendation is therefore a 60-task cohort selected from the 62
self-consistent tasks, leaving replacements available.

A current-runtime starting-state parse sweep passes 18 and fails 50 tasks.
That is not an eligibility filter: many tasks deliberately begin with missing
models, packages, or references that the agent must repair.

## Trajectory fidelity

The DBT runner persists task metadata, system message, raw model response,
extracted thought, stringified action, and observation. It lacks stable
tool-call IDs, timestamps, durations, exit codes, structured stdout/stderr,
token and cost records, parent/child relationships, dependency digests,
retry/fallback state, and typed action arguments. Future runs need a
loss-receipted adapter into Frankengate's canonical trajectory, with the
upstream transcript retained only as external provenance.

## Gotchas

- The README and evaluator disagree about the Lite database path.
  [README](https://github.com/xlang-ai/Spider2/blob/01a4c67c1e3f6ab9032716b050a927abbb245f65/spider2-lite/README.md#L6-L14),
  [evaluator](https://github.com/xlang-ai/Spider2/blob/01a4c67c1e3f6ab9032716b050a927abbb245f65/spider2-lite/evaluation_suite/evaluate.py#L409-L452).
- The Lite timeout argument is discarded.
  [Source](https://github.com/xlang-ai/Spider2/blob/01a4c67c1e3f6ab9032716b050a927abbb245f65/spider2-lite/evaluation_suite/evaluate.py#L226-L269).
- The Lite comparator ignores names, permits extra columns, and compares
  independent vectors.
  [Source](https://github.com/xlang-ai/Spider2/blob/01a4c67c1e3f6ab9032716b050a927abbb245f65/spider2-lite/evaluation_suite/evaluate.py#L84-L130).
- The DBT evaluator uses broad exception handling and silently maps failures
  to zero.
  [Source](https://github.com/xlang-ai/Spider2/blob/01a4c67c1e3f6ab9032716b050a927abbb245f65/spider2-dbt/evaluation_suite/evaluate.py#L35-L100).
- The DBT comparator has a non-reflexive NaN case.
  [Source](https://github.com/xlang-ai/Spider2/blob/01a4c67c1e3f6ab9032716b050a927abbb245f65/spider2-dbt/evaluation_suite/eval_utils.py#L109-L160).
- The DBT agent calls `env.step(action)` twice for ordinary tools.
  [Source](https://github.com/xlang-ai/Spider2/blob/01a4c67c1e3f6ab9032716b050a927abbb245f65/methods/spider-agent-dbt/spider_agent/agent/agents.py#L227-L270).
- Example-name filtering reads `id` while records use `instance_id`; the
  `dbt_only` option cannot be disabled and does not filter execution.
  [Source](https://github.com/xlang-ai/Spider2/blob/01a4c67c1e3f6ab9032716b050a927abbb245f65/methods/spider-agent-dbt/run.py#L50-L157).
- The runner interpolates destructive cleanup, leaves the execution network
  unrestricted, and persists raw potentially secret-bearing transcripts.
  [Runner](https://github.com/xlang-ai/Spider2/blob/01a4c67c1e3f6ab9032716b050a927abbb245f65/methods/spider-agent-dbt/run.py#L158-L217),
  [trajectory persistence](https://github.com/xlang-ai/Spider2/blob/01a4c67c1e3f6ab9032716b050a927abbb245f65/methods/spider-agent-dbt/spider_agent/agent/agents.py#L272-L287).

## Frankengate study contract

Split by database/schema family, never by random task. Keep benchmark content
out of the trace index that produces candidate skills. Compare these artifact
families independently and together:

1. schema-navigation and table/column selection heuristics;
2. enterprise metric definitions and business rules with provenance and
   validity intervals;
3. dialect/function guidance;
4. verified question-to-SQL examples;
5. failure-to-repair patterns from tool trajectories;
6. entitlement, refusal, read-only, timeout, and cost rules.

Score schema recall, execution and semantic correctness, materiality, repair
success and regression, tool calls, latency/cost, and authorization/refusal.
This tests the actual Frankengate claim: whether knowledge mined from prior
users and traces improves unfamiliar enterprise work without answer leakage
or authority bypass.
